# Watchlist 盘后提醒改造总档案

更新日期：2026-10-04  
范围：stock_frame/watch、stockdata/daily_update.sh 的既有调用链  
数据截止：本次验证所用本地指标数据截至 2026-09-18  
状态：代码、配置、状态迁移、文档和本地测试已完成；没有实际发送企微测试消息

## 一、目标和边界

Watchlist 的用途是监控用户已经在意的股票。当一只股票出现值得重新打开走势图的变化时，盘后提醒用户：

1. 为什么今天值得关注；
2. 当前属于初步观察、等待确认、确认增强还是风险状态；
3. 哪些支撑、压力和失效位来自可复核数据；
4. 后续出现什么收盘条件时，关注价值会增强或失效；
5. 大模型如何解释支持证据、反面证据和原关注逻辑。

系统不自动下单，也不把提醒分解释成胜率、上涨概率或预期收益。项目已有 B1 研究没有证明大模型看图、案例相似度或简单指标组合具有稳定盈利增量，因此大模型不参与候选筛选、评分和价位计算。

本次没有新增公共券商、行情或盘中 API。数据仍来自项目本地 stockdata/indicators 日线文件。

## 二、改造前的问题

### 2.1 默认规则过宽

改造前 watchlist 有 152 只股票，每只股票默认运行：

- 日线 B1，参数 no_good=true，实际只要求 J≤15；
- 周线 B1，参数 no_good=true；
- 靠近 MA60；
- 靠近 MA120；
- 靠近 MA240。

单独的低 J 和单独贴近任意均线都能形成事件，三条均线还会分别显示。同一只股票可能在一份报告中贡献多条低信息量规则。

### 2.2 第一次扫描产生大量信息

旧 archive.parquet 在 2026-09-18 留下 143 条规则事件：

| 旧规则 | 事件数 |
|---|---:|
| volume_dry_up | 52 |
| b1 | 33 |
| weekly_b1 | 28 |
| near_ma(MA60) | 12 |
| near_ma(MA120) | 11 |
| near_ma(MA240) | 7 |

这些是规则行数，不是 143 只不同股票。大量事件只是单一技术状态，不能直接代表值得打扰用户。

### 2.3 消息排版和模型调用

旧报告存在以下问题：

- 每只股票堆放现价、三条均线距离、52 周位置、量比和 thesis；
- 报告末尾展开所有持续中的状态；
- 模型自由生成六段文本，结构和长度不稳定；
- 每只触发股票调用一次模型，股票多时耗时随数量增加；
- 模型文字和程序事实混排，难以区分哪些价位来自数据、哪些是模型解释；
- 企微切分按字符数计算，没有按 UTF-8 字节数计算。

### 2.4 状态和研究样本

旧 state.json 只保存每条规则是否激活和开始日期，没有个股级最近提醒、提醒分和冷却信息。

旧归档按规则逐行保存。同一股票、同一天的多个规则会形成多行；同时没有区分真正展开提醒、被每日数量上限压下的候补和被冷却过滤的候选。

## 三、最终提醒链路

新的处理顺序为：

1. 读取 watchlist.yaml 和本地指标文件；
2. 计算每条规则当前是否成立；
3. 只把 False→True 的状态变化视为本次新触发；
4. 合并同一股票的全部当前有效规则；
5. 同类别信号只取最高权重，计算提醒分；
6. 应用组合门槛或重点信号豁免；
7. 应用个股交易日冷却；
8. 按风险、priority、提醒分和距 MA20 远近排序；
9. 前三只生成完整卡片和模型分析；
10. 其余达标股票生成候补摘要并归档；
11. 生成 Markdown 报告，有入选股票时才允许推送。

大模型位于筛选和排序之后。模型失败不会改变入选结果，也不会阻止规则版报告生成。

## 四、规则和提醒分

规则元数据定义在 rules.py。每条规则包含展示名、类别、权重、是否允许单独提醒和提醒类型。

| 规则 | 类别 | 默认分数 | 默认使用 | 可否单独进入候选 | 含义 |
|---|---|---:|---|---|---|
| b1 | daily_setup | 3 | 是 | 否 | 完整日线 B1 |
| b1_hook | confirmation | 5 | 是 | 是 | J 低位后的首次向上拐头 |
| weekly_b1 | weekly_setup | 2 | 是 | 否 | 完整周线 B1 |
| near_ma | support | 1 | 是 | 否 | 收盘位于指定均线上方且接近均线 |
| volume_dry_up | volume | 1 | 是 | 否 | 当日量相对 VMA20 收缩 |
| ma_reclaim | confirmation | 4 | 否 | 否 | 前一日在线下，当日收盘重新站回均线 |
| box_touch_lower | support | 5 | 按个股配置 | 是 | 人工箱体下沿得到承接 |
| box_breakdown | risk | 6 | 按个股配置 | 是 | 收盘首次跌破人工箱体下沿 |
| breakout | breakout | 5 | 否 | 是 | 放量收盘突破此前区间高点 |

完整日线 B1 沿用项目 kdj/layers.py 中 baseline_original：

- 趋势条件 GOOD 成立；
- J≤15；
- 日涨跌绝对值不超过 3%；
- 振幅不超过 7%。

b1_hook 另外要求：

- 趋势条件成立；
- J 低位后首次向上；
- 当日涨跌和振幅仍满足默认平静 K 线限制。

b1_hook 是提醒阶段定义，不是已经证明稳定盈利的买点。

### 4.1 同类信号不重复加分

系统按 category 合并，同一类别只取最高权重。

示例：

- 同时靠近 MA60、MA120 和 MA240，support 类仍只加 1 分；
- b1_hook 与 ma_reclaim 同属 confirmation 类，同时成立时只计较高的 5 分；
- 人工箱体承接与普通均线接近同属 support 类，同时成立时只计箱体承接的 5 分。

### 4.2 个股优先级

watchlist.yaml 支持：

- priority: high，提醒分加 1；
- priority: normal，不调整；
- priority: low，提醒分减 1。

优先级表示用户关注程度，不代表股票质量。

### 4.3 进入候选的门槛

普通信号必须同时满足：

- 提醒分不低于 4；
- 至少包含两个不同类别。

standalone=true 的重点或风险信号可以单独进入候选。

### 4.4 排序规则

候选依次按以下条件排序：

1. 风险提醒优先；
2. priority 高的优先；
3. 提醒分高的优先；
4. 同分时，距离 MA20 更近的优先；
5. 股票代码用于保证结果稳定。

提醒分只用于减少消息数量，目前没有经过独立历史验证，不能称为优选模型。

## 五、前三只和其他股票的处理

max_push_stocks 默认设置为 3。这里限制的是详细提醒名额，不是只保留三只股票，也不是选出三只自动买入标的。

### 5.1 前三只

前三只获得：

- 完整个股卡片；
- 触发规则；
- 提醒分及逐项组成；
- 支撑、压力、后续确认和逻辑失效；
- 大模型结构化解释；
- delivery_status=selected。

### 5.2 超出数量上限的候补

其他已经达到门槛的股票：

- 在消息末尾展示最多五只名称和提醒分；
- 超过五只时显示剩余数量；
- 在 archive.parquet 中保存完整触发快照；
- 标记 delivery_status=cap_suppressed。

候补不会因为同一个条件持续而第二天按顺序补发。这样可以避免把一次集中触发拆成多天噪音。如果候补后来出现新的、更强的状态变化，会重新参与排序。

### 5.3 被冷却过滤的股票

同一股票默认冷却 10 个交易日。冷却期内：

- 普通同级信号不重复提醒；
- 风险信号可以穿透冷却；
- 提醒分相比上次明显提高时可以穿透冷却；
- 达到门槛但被冷却的事件标记 delivery_status=cooldown_suppressed。

### 5.4 未达到门槛的弱变化

单独均线接近、单独缩量等弱变化不会形成提醒，也不会写入达标候选归档。股票仍保留在 watchlist 中；以后出现新的组合信号时可以再次进入评估。

## 六、关键价位和观察计划

snapshot 使用本地后复权指标数据计算，并通过 factor 转成行情软件可见价。

快照包含：

- 收盘价；
- 一日、五日和二十日收益；
- KDJ J；
- MA5、MA20、MA60、MA120、MA240 及距离；
- 均线近期斜率；
- 前二十日高低点和前六十日高点；
- 五十二周回撤和位置；
- 当日量相对 VMA20；
- ATR 相对收盘价。

支撑和压力候选来自：

- 五条均线；
- 前二十日低点；
- 前二十日和前六十日高点；
- watchlist 人工配置的箱体上下沿。

几乎重合的价位会合并显示。程序只展示离现价较近的两个支撑和两个压力参考。

观察计划按触发类型生成：

- B1 低位拐头：观察后续能否守住支撑并站稳 MA5；
- 放量突破：观察突破位能否守住，避免冲高回落；
- 箱体下沿承接：观察下沿能否持续守住并等待收盘转强；
- 风险信号：先检查原关注逻辑是否失效，不把下跌本身当作低吸理由；
- 普通组合：等待 J 低位拐头和收盘确认。

如果有人工箱体下沿，逻辑失效优先使用箱体下沿；否则使用前二十日低点。价位是观察参考，不自动提交交易。

## 七、大模型分析

### 7.1 调用位置

只有前三只详细提醒会进入模型输入。所有股票合并为一次请求，不再每只股票调用一次。

默认仍使用项目现有环境变量：

- GLM_API_KEY 或 ANTHROPIC_AUTH_TOKEN；
- LLM_BASE_URL；
- LLM_MODEL。

没有密钥、网络失败、模型返回非法结构时，程序继续使用完整的规则版报告。

### 7.2 输入信息

模型只接收：

- 股票代码和名称；
- 用户填写的 thesis；
- 提醒等级和提醒分组成；
- 本次新触发；
- 当前仍有效的规则背景；
- 日线量价和技术位置事实；
- 程序已经生成的观察条件和失效条件。

模型没有股票图像、新闻、行业数据、财务数据、盘中盘口或真实筹码数据。

### 7.3 提示词任务

模型必须按以下顺序分析：

1. 判断属于“仅进入观察、等待确认、确认增强、风险优先”之一；
2. 给出一至两条支持证据；
3. 强制给出至少一条反面证据、冲突或信息缺口；
4. 对照 thesis，说明符合、部分符合或无法判断；
5. 给出一至两条下一交易日收盘后可以验证的事件；
6. 说明最关键的失败路径。

提示词明确要求：

- 提醒分不是胜率、上涨概率或预期收益；
- 不得补充新闻、行业热度、基本面、资金流、盘口和筹码；
- 不得使用无法观测的“庄家成本”或“主力意图”；
- 不得给确定性涨跌预测；
- 不得直接下达买卖指令；
- 不重复程序已经计算的价格；
- 除股票代码外，文本字段不得添加阿拉伯数字、价格或百分比；
- 只返回 JSON。

### 7.4 输出结构

每只股票的模型输出包含：

~~~json
{
  "code": "股票代码",
  "state": "等待确认",
  "summary": "一句话阶段判断",
  "supporting_evidence": ["支持证据"],
  "contrary_evidence": ["反面证据或信息缺口"],
  "thesis_check": "原关注逻辑对照",
  "watch_for": ["下一步可验证事件"],
  "risk": "主要失败路径"
}
~~~

解析器会拒绝：

- 未知 state；
- 缺少反面证据；
- 在解释字段中添加阿拉伯数字；
- 非 JSON 输出；
- 返回不在本次输入中的股票代码。

本次本地验收没有实际调用外部模型，因此没有把任何 watchlist 数据发送到外部端点。提示词生成、结构解析、数字限制和失败回退已由本地测试覆盖。

## 八、企微报告

报告使用手机友好的分段 Markdown，不使用宽表格。每只详细提醒固定显示：

1. 股票名称、代码和提醒等级；
2. 本次新触发；
3. 现价、涨跌、J、量比和提醒分；
4. 分数组成；
5. 当前状态；
6. 支撑和压力；
7. 后续确认；
8. 逻辑失效；
9. 可选的模型解释。

末尾显示候补摘要和统一说明。

企微消息按 UTF-8 字节数切分，每段默认不超过 3500 字节，避免中文字符按字符数计算导致超过接口限制。2026-09-18 的三只规则版预览可以放入一条企微消息。

推送逻辑不再依赖模型成功：

- 有入选股票且指定 --push 时允许推送；
- 模型失败时推送规则版；
- 没有入选股票时不发送；
- --preview 永远不发送。

## 九、状态迁移和归档

### 9.1 state.json v2

新状态结构包括：

- schema_version=2；
- rules：每个股票、规则和参数提示的 active、since、last_transition；
- stocks：每只股票最近提醒日期、提醒分和等级；
- last_data_date。

旧版 key→[active, since] 会自动迁移。首次迁移默认只建立基线，不推送旧状态，避免升级当天刷屏。

2026-10-04 已使用本地 2026-09-18 数据完成迁移：

- schema_version：2；
- 规则状态数：1066；
- last_data_date：2026-09-18；
- 第一次迁移没有推送；
- 随后重复扫描为零新变化。

状态写入改为临时文件加原子替换，降低进程中断造成 JSON 损坏的风险。

### 9.2 archive.parquet

新归档按“股票—触发批次”存一行，不再把同一股票的每条规则拆成多行。主要增加：

- rule：本次新触发；
- active_rule：当前全部有效背景；
- signature：触发签名；
- score；
- tier；
- priority；
- delivery_status；
- 触发时刻的量价和位置快照。

追加新记录时保留旧版所有规则行，不会因为旧记录没有 signature 而错误去重。

## 十、配置

默认配置位于 watchlist.yaml：

~~~yaml
defaults:
  alerting:
    min_score: 4
    min_categories: 2
    cooldown_bars: 10
    cooldown_override_score: 2
    max_push_stocks: 3
    llm_max_stocks: 3
~~~

个股可以设置：

- enabled: false，暂停监控；
- priority: high|normal|low；
- thesis，记录为什么关注；
- inherit_defaults: false，只使用个股规则；
- alerting，覆盖个股门槛或冷却；
- rules，增加箱体、突破或重新站回等规则。

示例：

~~~yaml
- code: "sh600519"
  name: 贵州茅台
  priority: high
  thesis: 箱体下沿观察，守住后等待止跌确认
  rules:
    - rule: box_touch_lower
      params: {lower: 1300, upper: 1450}
    - rule: box_breakdown
      params: {lower: 1300}
~~~

截至本次改造，152 只股票中只有贵州茅台填写了个股 thesis。其他股票仍能获得通用技术解释，但模型无法判断其是否符合用户最初关注原因。后续最有价值的人工维护不是继续增加默认指标，而是为真正重要的股票补充简短 thesis 和人工关键位。

## 十一、命令和自动任务

在 stock_frame 目录执行：

~~~bash
python watch/scan.py --preview
python watch/scan.py
python watch/scan.py --llm
python watch/scan.py --llm --push
~~~

- --preview：无写入、无归档、无推送；把当前激活条件作为新变化展示；
- 无参数：正式更新状态和归档，但不调用模型、不推送；
- --llm：对前三只做一次批量解释；
- --push：有入选股票时推送；
- --bootstrap-alerts：首次状态建立时也输出旧条件，日常不建议使用。

stockdata/daily_update.sh 原有调用保持为：

~~~bash
python scan.py --llm --push
~~~

只有行情更新和指标计算成功后才执行盘后扫描。

## 十五、已知限制和后续评价

1. 提醒分是人工定义的消息优先级，没有经过独立历史验证。
2. 前三名不等于收益排序，也不代表比候补更可能上涨。
3. B1 低位首次拐头是观察条件，尚未证明是稳定买点。
4. 2026-09-18 预览是单个历史截面，不是提醒系统回测。
5. 本地行情当前截止到 2026-09-18，之后的正常频率需要随新数据观察。
6. 当前没有市场状态、行业状态、新闻和盘中数据。
7. 大多数股票没有 thesis，模型只能做通用技术解释。
8. 支撑、压力和失效位来自日线几何关系，不代表实际成交保证。
9. 本次没有实际验证外部模型端点返回质量，也没有向企微发送测试消息。

后续应冻结当前规则，积累 selected、cap_suppressed 和 cooldown_suppressed 的前瞻记录，再比较：

- 每日详细提醒数量和无提醒天数；
- 同股重复提醒间隔；
- 提醒后五日、十日和二十日路径；
- 最大有利和不利波动；
- 前三名相对同日候补的差异；
- 不同提醒分区间是否有单调关系；
- 模型解释是否帮助用户更快做出一致判断。

只有前三名相对候补在新增数据中持续出现扣成本后的收益或风险增量，才有理由把提醒分升级为择股分数。在此之前，它只负责控制消息优先级。
