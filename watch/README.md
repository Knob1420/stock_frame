# 盘后 watchlist

这个目录负责“我已经在意的股票，出现值得重新打开走势图的变化时提醒我”。它不是自动交易器，也不把每个超卖或贴均线状态都推送出来。

完整的改造背景、规则口径、状态迁移、模型提示词、验证结果和限制见 [Watchlist 盘后提醒改造总档案](WATCHLIST_REWORK_RECORD.md)。

## 提醒链路

1. rules.py 计算可复核的日线状态。
2. scan.py 把同一股票的状态合并。同类状态只取最高权重，三条均线不会重复抬高分数。
3. 只有新出现的重点信号，或至少两个类别合计达到门槛，才成为提醒候选。
4. 同一股票默认冷却 10 个交易日。风险信号或评分明显升级可以穿透冷却。
5. 每天最多详细推送 3 只；其余达标股票显示为一行候补摘要，并按未入选状态归档。
6. 大模型只解释这 3 只的量价和位置，一天最多调用一次。关键价位由程序计算，模型不能补数字。

当前默认信号：

| 信号 | 作用 | 权重 | 能否单独提醒 |
|---|---|---:|---|
| 原始日线 B1 完整条件 | 进入观察 | 3 | 否 |
| B1 低位首次拐头 | 等待确认 | 5 | 是 |
| 原始周线 B1 完整条件 | 多周期背景 | 2 | 否 |
| 靠近 MA60/120/240 | 支撑背景 | 同类最高 1 | 否 |
| 当日量不高于 VMA20 的 75% | 缩量背景 | 1 | 否 |
| 人工箱体下沿得到承接 | 个股计划价位 | 5 | 是 |
| 人工箱体下沿跌破 | 风险 | 6 | 是，且不受普通冷却限制 |

完整 B1 指原项目公式：趋势条件成立、J 不高于 15、日涨跌绝对值不超过 3%、振幅不超过 7%。低位拐头只是观察确认条件，项目历史研究尚未证明它是稳定正期望买点。

“提醒分”只是消息排序规则，不是胜率、上涨概率或预期收益：日线 B1 为 3 分、低位首次拐头 5 分、周线 B1 2 分、均线支撑和缩量各 1 分；人工箱体承接和放量突破为 5 分，箱体跌破风险为 6 分。相同类别只取最高分，priority: high 再加 1 分，priority: low 减 1 分。普通信号需要至少两个类别且合计不低于 4 分；重点和风险信号可以单独进入候选。

排序依次考虑风险信号、个股 priority、提醒分、距离 MA20 的远近。前三只展开，其他候补不会因原条件持续而逐日补发；若后续出现新的更强信号，会重新参与排序。所有达到门槛的股票都会归档，便于以后检验前三名是否真的优于候补。

## 日常命令

在 stock_frame 下执行：

~~~bash
python watch/scan.py --preview
python watch/scan.py
python watch/scan.py --llm
python watch/scan.py --llm --push
~~~

- --preview：把当前活跃状态当作新变化展示，不写 state.json、不归档、不推送。
- 无参数：更新状态并打印结果，适合本地核对。
- --llm：对最终入选股票做一次批量解释。没有密钥或调用失败时，规则版观察计划仍完整可用。
- --push：有入选股票才发企微或 Server酱；空结果不会发消息。它不再依赖 --llm 才能推送。
- --bootstrap-alerts：仅在确实需要把首次建立状态时的旧条件也发出来时使用。默认静默建基线，避免上线刷屏。

stockdata/daily_update.sh 已经使用 --llm --push，行情更新完成后会自动走这套链路。没有增加公共券商或行情 API。

## 配置个股

watchlist.yaml 的默认规则对所有启用股票生效。个股可以增加关注逻辑、优先级和专属价位：

~~~yaml
- code: "sh600519"
  name: 贵州茅台
  priority: high
  thesis: 箱体下沿观察，守住后等待止跌确认
  rules:
    - rule: box_touch_lower
      params: {lower: 1300, upper: 1450}
    - rule: box_breakdown
      params: {lower: 1300}
~~~

可用的个股字段：

- priority: high|normal|low：分别给组合评分加一、不变、减一。
- thesis：说明为什么关注；模型会对照它解释，缺失时只做通用量价分析。
- enabled: false：暂时停用该股票。
- inherit_defaults: false：不用默认 B1/均线规则，只运行该股票自己的规则。
- alerting：可逐股覆盖 min_score、min_categories、cooldown_bars。

另外提供两个非默认规则，按个股需要添加：

~~~yaml
rules:
  - rule: ma_reclaim
    params: {period: 20, tolerance: 0.02}
  - rule: breakout
    params: {period: 20, min_volr: 1.5}
~~~

前者表示收盘从均线下方重新站回且不过度远离，后者表示放量收盘突破此前区间高点。它们是提醒语义，不是已经通过回测的交易规则。

## 消息内容

每只股票固定显示：

- 为什么今天提醒；
- 收盘价、当日涨跌、J 值、量比、提醒分及其逐项组成；
- 来自均线、前期高低点或人工箱体的支撑与压力参考；
- 后续需要看到的确认；
- 哪个可观测条件会使本次逻辑失效；
- 可选的大模型状态解释。
- 最多五只候补摘要；完整候补保留在归档中。

报告不用表格，便于手机阅读；不再展开所有“持续中”状态。企微按 UTF-8 字节数切分，避免中文消息超过接口限制。

模型提示词要求它先判断“仅进入观察、等待确认、确认增强、风险优先”四种阶段之一，再分别输出支持证据、至少一条反面证据或信息缺口、原 thesis 对照、下一交易日可验证事件和主要失败路径。模型不能引入新闻、行业热度、基本面、资金流、盘口、筹码或所谓庄家行为，也不能把提醒分解释成概率。

## 状态、归档与当前降噪结果

- state.json 使用 v2 结构，分别记录规则状态和个股最近提醒。旧版会自动迁移，首次迁移静默。
- archive.parquet 对所有达到门槛的个股各存一行，并用 delivery_status 区分 selected、cap_suppressed 和 cooldown_suppressed；不再按每条规则重复存多行。
- reports/YYYY-MM-DD.md 保存当天完整提醒。

旧系统在 2026-09-18 的首次扫描留下 143 条规则事件，其中大量是单独的低 J、均线附近或地量状态。用同一数据截面预览新规则时，152 只股票中有 17 只达到组合门槛，最终只展示评分最高的 3 只。这个数字只验证消息降噪，不代表收益或胜率改善。

项目已有回测没有证明大模型看图、案例相似度或简单技术指标组合具备稳定盈利增量。因此大模型在这里用于解释和列观察条件，提醒规则是否提高实际决策质量，需要从新状态冻结后继续积累前瞻记录再评估。
