# 观察池归因改造设计（事件账本 + 计算视图）

> **状态：设计已批准（2026-09-18），暂缓实施。**
> 当前优先项是先回答"现有策略到底是否可行、在什么情况下可行"（见附录 A 可行性分析计划），其结论决定本设计的实施节奏。
> 来源：2026-09-18 用户评审（十条批评）+ 当日对话三轮裁决。

## 0. 背景与四个待回答的问题

工程流程已完整（数据→指标→信号→初筛→日报→入池→跟踪结案），但**证据逻辑未闭合**：目前只能得到"我入池的票胜率 X%"，无法归因。真正的四个问题：

```
① 原始 KDJ/量价公式有没有统计优势？
② 桶筛选在公式基础上有没有增加优势？
③ AI/人工从候选里挑选有没有增加优势？
④ 哪些买入理由在历史上反复兑现（相关性口径）？
```

## 1. 评审意见核对结论（2026-09-18，对照代码逐条验证）

**已经做了的：**

| 意见 | 实际情况 |
|---|---|
| 理由必须入池时冻结 | 已实现：`add_entry` 一次性写 `reason`/`reason_tags`（受控词表），无修改路径，复盘只读 |
| MFE/MAE | 部分已有：`max_up`/`min_dn` 即窗口盘中极值，3a 已盖日期戳；缺多期限收盘收益与首触时间 |

**确认命中的：**

| 意见 | 证据 |
|---|---|
| 只跟踪入池股 → 选择偏差 | `scan.py:213` 只跑 `watching`；candidates JSON 只存 top30，硬过滤前 100+ 信号不留痕 |
| 无对照组/基线 | 无任何市场基线记录 |
| 连续信号无去重 | `lookup.py:112` 逐信号日独立计案例，单边行情灌水桶统计 |
| cfg_version 不防挖历史 | 6c（8桶→18桶）本身就是看过数据后改的，现行桶胜率带此偏差 |
| 无法归因 | 以上总和 |

**修正/限定：**

- 未来函数：实盘前向循环无 look-ahead（排序只用截至当日的历史）；泄漏只发生在**回头评估筛选层**时 → 归因回放必须 point-in-time（walk-forward）
- hit/miss 标签：是对实际交易计划（+8/−5 止盈止损）的建模，**补多期限视图，不替换**
- 理由兑现率：只能按"相关性"解释，不能当因果；复盘措辞改相关性框架
- 核对中新发现：lookup 表只建一次永久缓存（`load_lookup` 有文件不重建），桶统计冻结在 2026-09-17——需明确重建时机与 asof

## 2. 已裁决的决定

| 分叉点 | 裁决 |
|---|---|
| 证据供给方式 | **C**：历史回放回答①②（作参考，带已知偏差）+ 冻结一版走前向，干净前向数据验证③④ |
| AI 推荐层记账 | **A**：研究流程必须落机器可读推荐记录（`ai_recs.jsonl`），AI 眼光与人工 override 分层可评 |
| 架构 | **方案一**：事件账本 + 计算视图。否决"统一跟踪状态机"（放弃 parquet 全史可重算的杠杆，纯浪费）；DuckDB 留作升级路径不现在上 |

**核心架构判断**：账本只记**事件**，Outcome 不落盘——parquet 全史在手（后复权历史行不因新除权改写，回放稳定），任何 `(股票, 日期)` 的多期限结局随时可重算。

## 3. 设计

### 3.1 Signal Ledger

`pool/ledger/signals.jsonl`（追加式，一行一事件，gitignore——可由回放再生）：

```json
{"date":"2026-09-18","sym":"sh600941","cfg_version":"kdj-default-38ab49c7",
 "j_low":8.3,"dd":-0.12,"age":23,"shrink":0.72,
 "bucket":"bull|j<=5|dd>-10",
 "pass_filter":true,
 "env":{"bull":true,"idx_chg20":-0.03,"breadth20":0.44},
 "amount":5.4e8,"chg":0.012}
```

- 每日 scan 尾部落账（全信号，不只 top30）；top30 成员继续由 `candidates-*.json` 记录
- `cfg_version` 逐事件盖章：公式换代后旧事件仍是旧公式的有效记录
- 体量 ~3-5 万行/年（~10MB），单文件

### 3.2 AI 推荐账

`pool/ledger/ai_recs.jsonl`（**跟踪进 git**，同 pool.json 定位——不可再生的案例资产）：

```json
{"date":"2026-09-18","sym":"sh600941","rec":"in","conviction":2,
 "tags":["缩量回调","J首拐"],"note":"关键理由一句话"}
```

研究流程写完 md 卡后**必须**落账（skill 硬步骤，日期与 candidates 一致性校验）。入池账继续用 pool.json 不动；淘汰理由留在日报 md 不强行结构化。

### 3.3 回放与 walk-forward（`pool/replay.py`）

- `backfill_signals()`：扫全白名单 parquet → 全史信号事件落账（幂等：`date+sym+cfg_version` 去重）
- **point-in-time 桶统计**：日期 D 的排序只用"信号日 ≤ D−11（窗口关死）+ 当日已知"的数据；逐日增量维护桶表，全史回放分钟级
- 归因回放对每个历史日 D 重建"walk-forward 纪律下的 top30"，与 candidates JSON 记录的实际 top30 并存对照（冻结表 vs 纪律化反事实，两者之差本身有信息量）
- 产物 `wf_top30-<cfg_version>.jsonl`（gitignore，可再生缓存）

### 3.4 归因报告（`pool/report.py`，按需触发不进日常链）

六队列 × 多期限口径：

| 队列 | 来源 |
|---|---|
| ① 全市场基线 | 每日白名单横截面中位数 |
| ② KDJ 信号全体 | signals.jsonl |
| ③ 硬过滤后 | pass_filter=true |
| ④ walk-forward top30 | 3.3 重建 |
| ⑤ AI 建议入池 | ai_recs rec=in |
| ⑥ 实际入池 | pool.json |

每队：n、+1/+3/+5/+10/+20D 收盘收益（中位数）、MFE/MAE、hit/miss/flat 率、**首次触线天数**（bar 序列现算）、相对①超额。去重口径（5 交易日冷却取首信号）与原始口径**并列展示**。

另两张表：**理由×结局**（reason_tag，相关性措辞）；**AI vs 人工 override 矩阵**（荐入已收/荐入未收/荐弃已收/荐弃未收，四格结局均可从 parquet 现算）。

### 3.5 冻结协议（`pool/research.json` + `docs/research_log.md`）

- 登记每次冻结的完整指纹：cfg hash / BUCKET_VER / CLOSE_CFG / 过滤参数 / 去重规则 / 冻结日 / 状态
- **评估门槛**：任一层 ≥30 个已结**前向**案例才允许下结论
- **换版纪律**：换参数 = 新 research id，旧前向案例不并入；回放数据只作产生假设的渠道，永远不作换版的"证据"
- 现行 lookup 表就此正式冻结（把"只建一次"的事实变成制度）；重建仅在换 research 版本时发生并明确 asof

### 3.6 流程与 skill 改动

- 研究流程：md 卡 → ai_recs.jsonl 落账（硬步骤）→ 入池照旧
- 新增对话命令"归因"：跑 report.py 给瀑布结论
- scan 主流程仅尾部加"signals 落账"一步；daily_update.sh 零改动
- 复盘报告措辞改相关性框架
- skill 改动经 skill-creator 流程产出（用户钉死的偏好）

## 4. 已知局限（须进报告脚注）

1. 幸存者偏差：parquet 只含当前在市股票，回放胜率系统性偏高
2. ST 5% 涨停拦不住
3. 18 桶方案系看过数据后所定（6c），回放桶胜率带 winner's curse，只作参考，冻结协议下不作数

## 5. 不做项

- 案例检索（case-based reasoning / k-NN）——账本建成后的未来视图，本轮不做
- DuckDB 分析仓——升级路径，量级不需要
- 前复权 K 线变换（复盘画图另行）
- Outcome 落盘存储——永远是计算视图
- pool.json 状态机语义改动
